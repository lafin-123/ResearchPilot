# 论文上下文第一版

## 使用

在“写作 → 稿件”选择当前稿件。中间是已保存正文的阅读区和章节导航，右侧“论文记忆”默认只展示研究主线、写作决定、待解决问题和来源状态。点击“打开编辑器”继续使用原有 DOCX/LaTeX 编辑；阅读区不覆盖正文。

需要修改研究记忆时点击“编辑记忆”，填写研究问题、假设、贡献、适用范围和术语。写作决定可标为待定、接受或拒绝；待解决问题可以注明章节。点击“返回摘要”只收起字段，不丢弃未保存输入。

先保存记忆，再选择“设为当前论文”。之后助手发送消息时，会在本机组装这篇论文的当前记忆和匹配来源；只有实际发送才把内容交给所选模型提供方。关联笔记也属于将发送的材料。停用后，下一轮请求会明确将此前的论文快照标为非当前材料。

“来源与证据”可关联当前项目已登记的文献、笔记、实验运行和图表。文稿正文在预览/助手使用前自动索引，其他来源不会被静默刷新。来源有变化或缺失时，旧片段不作为当前证据；“更新快照”明确采集来源的当前版本，不修改来源文件。

在“章节写作”填写章节和写作任务，查看片段、来源定位、哈希和覆盖范围。先核对，再“准备章节写作”；这一步只填入新会话草稿，不调用模型，不直接替换正文。准备时会重新核对版本和来源，拒绝过时预览。

## 保存范围

保存的论文记忆、已关联快照和当前论文选择位于本地 SQLite，按项目和稿件隔离。每次保存使用修订号；旧版本不能静默覆盖新版本。未保存输入只保留在当前应用进程的内存中，可以跨页面和项目恢复，但刷新/关闭应用会丢失，需及时保存。

项目备份包含论文记忆及来源快照；恢复使用新的项目与记录 ID，保留证据原始哈希。与 ID 相关的来源指纹在恢复后可能显示变化，需要复核并更新。备份是未加密的科研资料，请保存在可信位置。面板也可以单独导出脱敏 JSON 供审阅，不替代项目备份。

## 当前能力与限制

- 本地词项和章节匹配，最多组装24,000字符、12个片段；不是向量语义检索或全自动事实核验。
- 每篇论文最多100个来源（包含正文），每来源最多200,000字符。DOCX读取上限6MiB，解压条目另有上限；超出会明确提示。
- Markdown/LaTeX 保留可识别章节。DOCX仅正文文字，常见独立IMRaD标题采用保守推断，不保留完整样式和章节层级。
- 关联PDF采集最多100个物理页/200,000字符的文字层，记录页码及偏移。不做OCR，不完整理解图片、公式或表格结构；扫描页和截断范围会披露。
- 实验来源只包含已登记运行的状态、指标和产物目录元数据，不自动分析日志、环境或所有原始产物。图表只读取登记文件与结构化源，不运行绘图代码。
- 接受/拒绝代表作者的写作决定，不证明内容科学正确。论文自身的文字不能被当作独立实验证据。
- 当前只提示来源变化与需复核章节，不自动判断所有跨章节矛盾，也不自动批量修订论文。

## 验证

单元与集成测试覆盖修订冲突、跨项目隔离、真实文件哈希、来源删除/变化、异步变更、不安全路径、敏感内容脱敏和备份重映射。桌面测试使用隔离项目与本地模拟模型，核对真实发送请求中是否包含当前论文记忆及证据，不使用真实模型凭据。

本次验证记录：

- `npm run typecheck`、`npm test`：类型检查与456项测试通过。
- `npm run build`：生产构建通过。
- `node scripts/smoke-paper-context.mjs`：17项真实桌面检查通过，包含DOCX自动重建索引、旧来源排除、刷新不改原文件、跨项目拒绝、未发送章节草稿、真实流式请求自动带入记忆，以及重启保留。
- `node scripts/smoke-desktop.mjs`：现有文献、实验、稿件、图表和工具连接流程通过。

测试先验证缺少实现、旧修订覆盖、文件读取与指纹不一致、来源解绑竞态、草稿丢失和过期预览等失败，再验证对应修复。尚未对真实论文集合做检索质量基准，也未评估模型生成稿件的科学质量。
